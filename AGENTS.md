# Муроблоки — правила разработки

## Архитектура

- Сохраняй существующие зоны ответственности. В рамках согласованного перехода на Vue 3 + Vite + TypeScript разрешён постепенный перенос файлов/компонентов; не переписывай чистые игровые правила ради смены стека.
- Не меняй игровую логику без прямого требования. Согласованное исключение ближайшего релиза: убрать обязательную небольшую фигуру из обычной генерации, сохранив гарантию допустимого хода при его существовании и конечность защитного подбора.
- Не меняй формат сохранений без миграции.
- Не переписывай рабочие модули с нуля.
- Соблюдай SOLID, DRY, KISS, YAGNI.
- Согласованный объём и решения хранятся в `docs/release-scope.md`; сверяй связанные ТЗ и явно отмечай отложенный объём.

- Следующий согласованный этап 1.3.0: модуль 2048 по двум ТЗ `docs/specs/aidagame_2048_*`; независимые партии/рекорды, числовые плитки без рисунков, общий импорт/экспорт и совместимый откат на 1.2.0. Правила и оформление 1010! сохраняются.

## Изменения

- Делай минимальные точечные правки.
- Не добавляй функции вне задачи.
- Не удаляй файлы без обоснования.
- Не устанавливай зависимости без необходимости.
- Сохраняй действующий UI-дизайн, палитры и внутренние ID. Согласованные дополнения: раздел экспорта/импорта внизу настроек, состояния ошибок/конфликтов и исправление слоёв/анимаций поля. Накопленные счётчики и сервер отложены.

## Проверки

- Запускай npm test после изменений.
- Добавляй тесты на новые сценарии.
- Проверяй совместимость сохранений.
- Проверяй мобильную адаптацию.
- Сообщай о непроверенных сценариях.
- После внедрения стека запускай отдельную проверку типов и production build, unit/integration и браузерные проверки.
- Проверяй ресурсы и PWA под `/aidagame/`, оба режима всех шести тем, старые сохранения v1, атомарный импорт и конфликты вкладок.
- Измеряй размер и производительность production-сборки до/после; не обещай отсутствия регрессии без замеров.
- Сам формулируй технические подзадачи, веди матрицу «требование → реализация → проверка → результат». Не перекладывай составление задач на пользователя.

## Git

- Работай в отдельной ветке.
- Показывай список изменённых файлов.
- Не используй git push --force.
- Не объединяй PR и не публикуй релиз
без отдельного подтверждения.
- Для релиза 1.2.0 отдельное разрешение на публикацию по `https://dulova.github.io/aidagame/` получено в текущем задании; это не даёт разрешения на будущие релизы.
- Для версии 1.3.0 с 2048 пользователь отдельно разрешил публикацию 30 октября 2026 после локальной приёмки: «Публикуй, всё хорошо». Разрешены загрузка ветки, PR, merge после CI, развёртывание Pages и проверка опубликованной версии. Это не даёт разрешения на следующие выпуски.
