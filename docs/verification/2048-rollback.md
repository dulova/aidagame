## Локальный возврат

Сначала сохранить/закоммитить текущую работу и экспортировать актуальные сохранения через настройки приложения. Затем из корня проекта:

```bash
git status --short
git switch -c restore/pre-2048 rollback/pre-2048-20261030
npm ci
npm run check
npm run preview -- --host 127.0.0.1
```

Это создаёт отдельную ветку восстановления, сохраняя новую реализацию и историю. Не применять `reset --hard`, force push или удаление базы. Возврат к новой реализации после завершения проверки:

```bash
git switch feat/2048
npm ci
npm run check
```

Для восстановления из архива исходников распаковать его в **новую пустую папку**. Для восстановления истории `git clone /путь/к/history.bundle /новая/папка`; исходные незакоммиченные документы находятся в tar-архиве, не в bundle. Не распаковывать поверх текущего рабочего каталога.

## Совместимость пользовательского прогресса

Физическая версия IndexedDB остаётся **2**, имя `muroblocks-v1` сохранено. 2048 добавляет только `items['game:2048']` и `records['2048']`. Формат и ключи 1010! не изменены; общая ревизия сохраняет защиту от конкурирующей записи.

Проверены два уровня:

- Unit/integration: новый клиент сохраняет обе игры → неизменённый репозиторий 1.2.0 меняет 1010!/настройки → новый клиент восстанавливает обе партии и рекорды.
- Chromium с настоящими Service Workers: установленная 1.2.0 с партией 1010! → 1.3.0, ход в 2048 и офлайн-перезапуск → 1.2.0, изменение рисунка → повторная 1.3.0. Счёт 1010!, счёт/рекорд 2048 и новые настройки сохраняются.

При возврате к 1.2.0 игра 2048 скрыта, её ключи остаются в базе. Старый клиент безопасно отклоняет JSON с двумя играми; для такого файла нужен клиент 1.3.0. **Импорт старого файла в 1.3.0 — другое действие:** после предупреждения он намеренно полностью восстанавливает копию, сбрасывая отсутствующие в ней данные 2048.

Снимок исходников и Git bundle **не содержат прогресс из браузеров пользователей**. Перед будущим обновлением/откатом сохранить JSON вне приложения. Не удалять IndexedDB, данные сайта или приложение ради обновления. Возврат к версиям **до 1.2.0**, использовавшим IndexedDB v1, этой проверкой не покрывается.

## Если позднее понадобится откат публикации

После отдельного разрешения развернуть проверенный `dist` 1.2.0 либо собрать код из сохранённого тега. Origin/base `/aidagame/` должны сохраниться. Публикация кода не требует сброса данных сайта.

В браузере дождаться безопасного момента, вернуться в меню, перезагрузить страницу и принять «Обновить». В тесте переход начинается с повторного открытия уже установленной PWA: Workbox отличает первую установку в текущем документе от обновления установленного клиента. Если предложение появилось прямо в первой сессии установки и кнопка не перезагрузила документ, повторно открыть страницу и принять обновление; не очищать данные.

Установленная PWA и Safari на физическом iPhone требуют отдельной ручной проверки перед публикацией; автоматический прогон WebKit не заменяет эту проверку.
