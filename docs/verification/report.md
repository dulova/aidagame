# Приёмка aidagame 1.2.0

Дата: 30 октября 2026. Исходная версия: `c4726fe118183a569b22e97a8a7d5b3d726f7b7b`. Согласованные требования — [release-scope.md](../release-scope.md). Бренд, палитры, идентификаторы и игровые правила сохранены, кроме согласованного удаления обязательной маленькой фигуры при генерации тройки.

## Выполненные проверки

- `npm run check`: TypeScript, **23 unit/integration-теста**, production build, автоматические бюджеты размера — успешно.
- `npm run test:e2e -- --workers=1`: **26 успешных, 10 намеренно пропущенных**, ошибок нет. Chromium desktop, Chromium с мобильным профилем, WebKit с профилем iPhone 13. Пропуски относятся к мыши в сенсорном профиле, CDP-касанию вне мобильного Chromium и обновлению прежнего интерфейса мышью в мобильном профиле.
- Production-сборка тестируется по `/aidagame/`, а не по корню `/`.
- `npm audit --omit=dev`: у runtime-зависимостей известных уязвимостей нет. Полный аудит показывает четыре низкоприоритетных предупреждения в цепочке сборочного Workbox/deepmerge; эти библиотеки в runtime игры не поставляются. Принудительное понижение PWA-плагина не выполнялось.
- Размеры: все JS+CSS, включая ленивый chunk игры и Service Worker, около **57,4 КиБ gzip** при лимите 150 КиБ; полный `dist/` около **198,2 КиБ** при лимите precache 1 МиБ. Полный `dist/` — консервативная верхняя граница precache. Проверка размеров включена в CI.

## Производительность

Метод: локальные HTTP-серверы с gzip, Chromium 143.0.7499.111 на macOS arm64, viewport 390×844, CPU slowdown ×4, сеть 1,6 Мбит/с download / 0,75 upload, задержка 150 мс. Пять новых браузерных контекстов на версию; холодный старт и затем офлайн-перезагрузка из кэша. Готовность — доступна кнопка запуска игры. Это воспроизводимая эмуляция, не измерение физического телефона или скорости GitHub CDN.

| Медиана | Исходная версия | Vue 1.2.0 | Бюджет |
| --- | ---: | ---: | ---: |
| Холодный старт | 865,5 мс | 892,4 мс | ≤3000 мс |
| Повторный офлайн-старт | 136,6 мс | 146,8 мс | ≤1000 мс |

Холодный старт вырос примерно на 27 мс в этом профиле, повторный — на 10 мс. Это не доказательство равной скорости на всех устройствах. Исходные значения всех прогонов и параметры — в [performance.json](performance.json).

Во время пяти drag-прогонов новой версии не зарегистрировано интервалов requestAnimationFrame длиннее 50 мс; максимумы около 9,4 мс в этой среде. Эти значения отражают частоту среды измерения и не доказывают 60 FPS на iPhone. Движение меняет transform плавающей фигуры; БД записывается после принятого хода, а не на каждом кадре. Поле сохраняет 100 фоновых узлов. Длительность очистки управляется CSS; при reduced-motion ожидание анимации сокращается.

Воспроизведение сравнения:

# при необходимости PLAYWRIGHT_CHROME_PATH=/path/to/chrome

## Совместимость, резервная копия и ограничения

- До организации исходников создан архив стабильной версии и проекта: `aidagame-backups/2026-10-30_13-13-25_MSK/stable-and-project-before.tar.gz` рядом с локальным проектом. Рабочая реализация подготовлена в отдельной ветке. Git-история и remote не заменяются.
- Версия БД — 2, снимок игры — 1, JSON-экспорт — 2. Старый JSON v1 читается. Партия, настройки и рекорд коммитятся вместе; при неудаче состояние в памяти остаётся доступным для экспорта и retry. Накопленная статистика не создаётся.
- IndexedDB — основной источник. При его отказе нет тихого переключения записи на localStorage, создающего расходящиеся копии; старый localStorage используется при миграции. Разные старые копии требуют явного выбора.
- Реальный iPhone недоступен. Вручную остаются установка из Safari на экран Домой, касание/перетаскивание в standalone, safe area при изменении браузерных панелей, повторный запуск без сети и обновление установленной иконки. WebKit с профилем iPhone — полезная автоматическая проверка, но не физическое устройство.
- Полный аудит dev-зависимостей содержит низкоприоритетные замечания; отдельно запланировано обновление при появлении совместимого исправления цепочки Workbox. Runtime audit чист.
- Серверное резервирование, аккаунты, синхронизация, накопленные счётчики, игровые экраны 2048/Tap Match не входят в этот релиз.
- Сохранения привязаны к origin. Файл нужно экспортировать до перехода с localhost/другого домена. Замена GitHub Pages сама по себе не переносит чужой origin.

## Обновление и откат

Для пользователя: согласиться на обновление в приложении, после чего загрузится новая оболочка; база мигрирует без удаления партии. При ошибке записи — повторить или экспортировать актуальную память; при конфликте — экспортировать свою версию либо явно загрузить свежую.

Не откатывать автоматически базу версии 2 до 1. Сначала сделать JSON-экспорт и предпочтительно выпускать совместимое исправление поверх 1.2.0. Старое приложение может отказаться открывать более новую IndexedDB; перед использованием старого кода нужна отдельная проверка/обратная миграция. Удаление базы не является способом исправления или штатного отката.
