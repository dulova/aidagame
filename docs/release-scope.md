# aidagame — согласованные требования 1.2.0 и 1.3.0

Статус: согласовано пользователем и реализовано в версии 1.2.0. После согласования пользователь отдельно поручил довести приложение до публикации на GitHub Pages. Фактические проверки, результаты и ограничения приведены в [отчёте приёмки](verification/report.md).

Основание: решения пользователя в текущем чате. Этот документ фиксирует объём и снимает перечисленные противоречия между ТЗ. Остальные требования четырёх ТЗ продолжают действовать в своих зонах ответственности. README описывает фактическую реализацию. Отложенный объём не считается реализованным.

## 1. Уже выбранные решения

| Область | Решение |
| --- | --- |

| Генерация | В новой тройке есть допустимый ход, если он вообще возможен; обязательной небольшой фигуры нет |

| Публикация | Отдельно разрешена пользователем в этом задании: проверка CI, merge и размещение на GitHub Pages; GitHub Release не создаётся |

## 2. Формулировки обязательного поведения

### Данные

Сохранить совместимость с IndexedDB `muroblocks-v1`/`items`, ключами `game:block-puzzle` и `app:settings`, прежним fallback localStorage и игровым снимком `version: 1`. Имя базы/ключи не менять ради переименования репозитория. Из старого `best` сформировать отдельный рекорд; текущую статистику партии сохранить. Не создавать историю прошлых партий.

Разделять версии схемы базы, снимка игры и формата файла. Все миграции валидируются до записи, откатываются при отказе и безопасно повторяются. Исходные данные не удаляются вместо миграции. При обнаружении разных IndexedDB/localStorage-снимков не считать больший счёт доказательством большей свежести.

Ход, отдельный рекорд и необходимые метаданные сохраняются согласованно. Успех операции подтверждается только после завершения транзакции. При отказе актуальное состояние остаётся в памяти, пользователь видит предупреждение и может повторить сохранение или экспортировать текущую версию.

Проверка ожидаемой ревизии и запись выполняются в одной транзакции. BroadcastChannel используется для уведомления, но отсутствие этого API не позволяет тихо перезаписать более свежие данные. Конфликтующая вкладка прекращает запись и предлагает загрузить актуальную версию либо экспортировать свою.

### Экспорт/импорт

В конце содержимого настроек, после рисунков и перед возвратом, разместить раздел «Сохранения»: «Экспорт сохранений», «Импорт сохранений». На мобильном две кнопки вертикально. Добавить краткое пояснение, что файл сохраняется вручную и автоматической серверной копии нет.

Экспорт охватывает все реализованные игры, текущие партии и их статистику, отдельные рекорды и общие настройки. Поддержать импорт старого `{format: "muroblocks-backup", version: 1, ...}` и нового `{appId: "muroblocks", exportVersion: 2, ...}`. Поле best старого файла переносится в отдельный рекорд. Неизвестные более новые версии/неподдерживаемые модули безопасно отклоняются до записи.

До подтверждения показать дату копии, игру, состояние партии, счёт и рекорд; предупредить о полной замене. Кнопки «Отмена» / «Восстановить». Импорт не объединяет партии и не оставляет автоматически больший локальный рекорд. Весь файл сначала валидируется/мигрируется, затем записывается одной транзакцией с проверкой ревизии. Ошибка любого шага и отмена сохраняют прежние данные. Согласованное резервирование текущего локального состояния перед заменой желательно, но не заменяет атомарность импорта.

### Изображения, генерация и анимации

Исправить пути/обработку SVG-масок для всех состояний: превью, фигуры в слотах, перетаскивание и блоки поля. Проверить отсутствие 404 и фактическое отображение в development, production по `/aidagame/`, обоих режимах тем и офлайн. Причину сообщённой пользователем ошибки подтвердить запросами браузера; наличие файла на диске само по себе не подтверждает исправление.

Убрать условие обязательной небольшой фигуры не только из требований тестов, но и из фактического фильтра обычной генерации. Оставить детерминированные проверки допустимого хода, конечный предел попыток и защитный подбор при его исчерпании; полноразмерное поле корректно завершает партию.

Сетка из 100 фоновых клеток постоянна. Только отдельные цветные блоки уменьшаются каскадом; логика/очки не пересчитываются по кадрам. Установка плавно доводит размер 88% до 100%, отменённое размещение быстро возвращает фигуру в слот. Геометрия поля не скачет, проекций и подсветок позиции нет. При уменьшенном движении сокращаются и эффект, и ожидание управления.

### Сборка и PWA

Vue-шаблоны компилируются на сборке; компилятор шаблонов в runtime, инструменты Vite/TypeScript и тестовые библиотеки не загружаются игроку. Не добавлять тяжёлые UI/анимационные пакеты без необходимости. Поддержка новых игр — контракт и каталог без фиктивных игровых экранов.

Сборка с base `/aidagame/`; manifest/start_url/scope/SW и ресурсы используют корректный базовый путь. В CI — установка из lock-файла, проверка типов, тесты, build и браузерные проверки production-сборки. Публиковать только `dist/`, не `docs/` и исходный корень.

Vite PWA обеспечивает согласованное кэширование production-ресурсов. Отложенные chunks, настройки и импорт/экспорт должны работать офлайн после подтверждённой готовности кэша. Обновление предлагается пользователю и не прерывает жест, ход, импорт или несохранённые данные. Проверить переход с прежнего `sw.js` и сохранность IndexedDB.

Смена origin не переносит данные между доменами; при переходе с localhost/прежнего домена нужен экспорт из прежней установки и импорт на новом адресе.

## 3. Согласованные бюджеты производительности

Vue добавляет runtime по сравнению с нынешним приложением без зависимостей. Отсутствие заметного ухудшения нужно подтвердить сравнением production-версий, а не обещанием по названию стека.

- JS+CSS первой загрузки: до 150 КиБ после gzip.
- Обязательный precache PWA: до 1 МиБ файлов без сжатия.
- Готовность меню к вводу на фиксированном мобильном профиле: медиана до 3 с при холодном старте, до 1 с при повторном старте из кэша.
- Не менее 5 прогонов каждой версии в одинаковых условиях; отдельно размер, загрузка, кэш и игровое взаимодействие. В отчёте — браузер, CPU/устройство, сеть, viewport и медианы; реальный iPhone проверяется при доступности.
- Профилирование drag/очистки: изменения кадра не должны выполнять запись в БД или перестраивать всю сетку. Цель — плавное движение на устройстве с экраном 60 Гц, с отчётом по длинным задачам и пропускам кадров.

Это согласованные пороги; измерения приведены в отчёте приёмки. Если порог недостижим, представить причину и оптимизацию до приёмки; не менять бюджет молча.

Для ориентира исходная версия c4726fe содержит 19 файлов приложения общей длиной 95 599 байт; сумма gzip-размеров отдельных JS-файлов — 12 257 байт. Это оценка файлов на диске, не измеренный сетевой трафик, не новый bundle и не замер времени загрузки. Исходная версия и сборка 1.2.0 сравнены скриптом `scripts/benchmark.mjs`, по пять прогонов; данные сохранены в `docs/verification/performance.json`.

## 4. Порядок работ, которые агент формулирует и выполняет сам

1. Зафиксировать согласованные требования в отдельной ветке.
2. Создать проверки исходных механик/сохранений и профили исходной версии.
3. Подключить Vite/TypeScript, затем постепенно перенести интерфейс на Vue без изменения палитр и правил.
4. Внедрить отдельные рекорды, миграции, ревизии, ошибки и конфликты вкладок.
5. Реализовать пользовательский экспорт/импорт в настройках, включая атомарный откат и старый формат.
6. Исправить SVG-пути, генерацию и устройство анимаций поля; покрыть согласованные отличия проверками.
7. Подготовить CI, Pages-сборку и PWA; проверить root/subpath, обновление и offline. После успешных проверок выполнить разрешённую публикацию.
8. Сравнить производительность и сделать отдельный проход по вёрстке на 390×844, 320×568 и 1440×900.
9. Предоставить матрицу приёмки, ограничения, способ отката и обновлённый README. Отдельное разрешение на публикацию получено в текущем задании.

Статус: реализован и проверен локально 30 октября 2026, принят пользователем; публикация отдельно разрешена сообщением «Публикуй, всё хорошо». Разделы 1–6 выше фиксируют выпущенную 1.2.0; исключение новых игр относилось к тому выпуску.

- Каталог открывает реальную 2048: 4×4, две стартовые плитки, один spawn 2/4 (90/10) после изменившего поле хода, очки за независимые слияния, продолжение после 2048 без окна победы.
- Свайпы/стрелки без автоповтора, отмены, подсказок и экранных направлений. Раздельные фазы перемещения, слияния и появления; неподвижные 16 фоновых клеток, reduced-motion.
- Числовые палитры для шести тем в двух режимах. Рисунков на числовых плитках нет; настройка «Рисунок блоков 1010!» сохраняется независимо.

- Общий экспорт v2 содержит обе игры. Полный атомарный импорт старого файла сбрасывает отсутствующую 2048 только после подтверждения; при наличии местных данных показывает прямое предупреждение. Меньшие рекорды восстанавливаются точно из файла.
- Ошибки записи, экспорт из памяти, повтор без повторного хода, общая ревизия и конфликт вкладок действуют для обеих игр. Повреждение одной партии изолировано; исходные записи доступны для диагностики, сброс требует явного действия.
- Проверены старые сценарии 1010!, обновление PWA с 1.2, откат на 1.2 и повторное обновление без потери данных. Бюджеты загрузки сохраняются.
- Сервер, аккаунты, накопленные счётчики и Tap Match остаются вне объёма. Отдельное разрешение на публикацию 1.3.0 получено после приёмки. Оно не распространяется на будущие выпуски.
