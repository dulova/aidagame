# ТЗ. Экраны приложения, содержание и вайрфреймы

> Согласованная редакция релиза 1.2.0. Объём: [решения релиза](../release-scope.md); фактические проверки и ограничения: [отчёт](../verification/report.md).

> Следующий этап 2048 описан отдельно: [игровые правила](aidagame_2048_gameplay_spec.md) и [интеграция/UI/приёмка](aidagame_2048_integration_spec.md). Это подготовка будущего модуля, не функция версии 1.2.0; все решения согласованы, реализация разрешена (§16 игрового ТЗ).

## 1. Общие требования

Приложение «Муроблоки» включает четыре основных экрана:

1. Главное меню с каталогом головоломок
2. Настройки оформления
3. Игровой экран для каждой головоломки
    1. 1010!
    2. 2048 — пока только недоступная карточка каталога.
    3. Tap Match — пока только недоступная карточка каталога.
4. Завершение партии

Для каждого экрана необходимо разработать мобильный и десктопный вайрфрейм.

## 2. Приоритет проектирования — мобильные устройства

Нужно следить, чтобы весь контент и все элементы запущенной игры помещался на одном экране айфона и не допускать скроллинга.

Необходимо придерживаться описанной ниже структуры элементов. Допускается оптимизация расстояний, размеров и адаптивного расположения без изменения функционального состава и визуальной иерархии экранов.

Нельзя самостоятельно добавлять новые игровые механики, счётчики, валюты, достижения или кнопки, не предусмотренные техническим заданием.

## 3. Главное меню

Главное меню — стартовый экран приложения.

Основные переходы:

- Главное меню → Игровой экран.
- Главное меню → Настройки.
- Настройки → Возврат на предыдущий экран.
- Игровой экран → Главное меню.
- Игровой экран → Завершение партии (автоматически, если больше нет допустимых ходов).
- Завершение партии → Новая игра.
- Завершение партии → Главное меню.

Возврат из игровой партии в меню не должен уничтожать сохранённую партию.

## 4. Экран настроек

![image.png](%D0%A2%D0%97%20%D0%AD%D0%BA%D1%80%D0%B0%D0%BD%D1%8B%20%D0%BF%D1%80%D0%B8%D0%BB%D0%BE%D0%B6%D0%B5%D0%BD%D0%B8%D1%8F,%20%D1%81%D0%BE%D0%B4%D0%B5%D1%80%D0%B6%D0%B0%D0%BD%D0%B8%D0%B5%20%D0%B8%20%D0%B2%D0%B0%D0%B9%D1%80%D1%84%D1%80%D0%B5%D0%B9%D0%BC%D1%8B/image%201.png)

**Раздел «Цветовая тема» и режим:**

Шесть тем: Зима, Весна, Лето, Осень, Пастель, Ай Да Настя. Отдельный переключатель светлого/тёмного режима применяется к выбранной теме. Тема и режим сохраняются независимо; текущие палитры и стартовый выбор не меняются.

- Сетка из всех доступных карточек тем.
- Каждая карточка содержит миниатюру палитры, включая цвета игровых блоков.
- Название темы.
- Отметка выбранного варианта.

**Раздел «Рисунки на блоках»:**

- Сетка из шести карточек: Однотонный, Лапка, Снежинка, Сердечки, Лист, Тыковка.
- Каждая карточка содержит визуальный образец оформления блока и название набора.
- Отметка и выделение акцентным цветом выбранного варианта.

**Раздел «Сохранения»:**

Это последний содержательный раздел страницы, после рисунков и перед навигацией возврата. В нём две кнопки: «Экспорт сохранений» и «Импорт сохранений»; на смартфоне вертикально. Кратко пояснить: файл нужно сохранить самостоятельно, автоматической серверной копии нет.

Экспорт скачивает JSON всех реализованных игр, настроек и отдельных рекордов. Импорт открывает выбор файла и предварительный просмотр с датой копии и сведениями о партии/рекорде. Показать предупреждение: после подтверждения все поддерживаемые данные заменяются данными из файла, включая меньший рекорд. Действия: «Отмена» / «Восстановить». Подготовить состояния проверки, успешного завершения, неподходящего файла, неизвестной версии, отказа записи и конфликта вкладок. До подтверждения и успешной транзакции данные не меняются.

Накопленные счётчики всех партий и новый экран статистики отложены. Статистика текущей партии остаётся частью сохранения.

### Композиция

На смартфоне карточки тем располагаются в две колонки, карточки рисунков — в три колонки.

На десктопе количество колонок может увеличиваться с сохранением удобочитаемости.

При необходимости экран настроек может прокручиваться вертикально.

Выбор оформления применяется немедленно. Кнопка «Сохранить» для оформления не нужна; экспорт и импорт — самостоятельные операции с файлом.

### Композиция

Поле — главный визуальный элемент страницы.

На мобильном устройстве элементы располагаются вертикально:

1. Шапка.
2. Счёт.
3. Игровое поле.
4. Три фигуры.
5. Кнопка новой игры.

Игровое поле должно занимать максимально возможную полезную ширину с соблюдением внешних отступов.

Слоты должны предоставлять достаточно пространства для уверенного захвата фигуры пальцем.

Игровой экран по возможности должен помещаться по высоте без вертикальной прокрутки.

На небольших экранах необходимо уменьшать отступы и второстепенные элементы, сохраняя читаемость поля и доступность фигур.

На десктопе главная, настройки и игра используют один компактный центрированный контейнер. Поле, панель фигур и кнопки совпадают по ширине с шапкой. На телефоне поле сохраняет полезную ширину экрана при изменении высоты браузерных панелей и во время игры; постепенное уменьшение недопустимо. Скругления пропорциональны клеткам, без превращения их в круги.

На всех экранах исключить выделение интерфейса долгим касанием и масштабирование щипком, сохранив прокрутку одним пальцем. В подвале ссылка aidanastya подчёркнута и использует акцентный цвет.

### Дополнительные состояния

Необходимо подготовить отдельные макеты:

- Обычная партия.
- Захват и перемещение фигуры.
- Успешная установка фигуры.
- Недопустимое размещение.
- Очистка линии: короткий каскад уменьшения отдельных цветных блоков над неподвижными 100 клетками подложки; логическая очистка одновременна.
- Выбранная фигура при управлении мышью.

При перетаскивании не показывать предварительную проекцию установки на поле.

При попытке неверного размещения не использовать агрессивную красную подсветку.

Если пользователь начинает новую игру при незавершённой партии, предусмотреть подтверждение сброса прогресса.

## 6. Экран завершения партии

### Содержание

**Центральная область:**

- Небольшой декоративный элемент.
- Заголовок «Игра окончена!».
- Короткая дружелюбная надпись.

**Результаты:**

- Итоговый счёт.
- Рекорд.
- При установлении нового рекорда — ненавязчивое поздравление.

**Действия:**

- Основная кнопка «Играть снова».
- Второстепенная кнопка «В меню».

### Композиция

Центральная вертикальная композиция.

Основной визуальный акцент — полученный результат.

Кнопка повторной игры должна быть заметнее кнопки выхода в меню.

Не использовать соревновательный, агрессивный или осуждающий тон.

## 7. Адаптивные вайрфреймы

Необходимо разработать макеты для следующих контрольных размеров:

- Мобильный: 390×844 px.
- Компактный мобильный: 320×568 px.
- Десктоп: 1440×900 px.

Для компактного мобильного экрана разрешается адаптация размеров и отступов. Если все элементы физически не помещаются, приоритет отдаётся удобству игрового поля и управления, а не абсолютному запрету прокрутки.

Для каждого экрана необходимо определить:

- Размеры и положение основных зон.
- Порядок элементов.
- Минимальные отступы.
- Размеры интерактивных областей.
- Максимальную ширину контентной области.
- Поведение при изменении ширины и высоты экрана.

## 8. Порядок подготовки макетов

Работа выполняется последовательно.

**Этап 1.** Низкодетализированные вайрфреймы всех основных экранов. Без окончательных цветов, шрифтов и декоративного оформления.

**Этап 2.** Согласование структуры, размеров и расположения элементов.

**Этап 3.** Разработка полноценного UI-дизайна с использованием цветовых тем и визуальных правил из ТЗ.

**Этап 4.** Подготовка адаптивной вёрстки, визуальных состояний, компонентов и дизайн-токенов.

На этапе проектирования не требуется реализация игровой механики.

## 9. Критерии приёмки

- Каждый экран содержит все предусмотренные элементы.
- Навигация между экранами однозначно определена.
- Первичные и второстепенные действия визуально различаются.
- На смартфоне приоритет отдан полю и управлению фигурами.
- Состояния интерфейса представлены отдельными макетами.
- Адаптивное поведение не требует дополнительных решений разработчика.
- Финальный дизайн соответствует согласованным вайрфреймам с добавленным разделом сохранений.
- Все SVG-рисунки доступны без 404 под `/aidagame/`, в PWA и офлайн.
- Поле, настройка темы и режим не сбрасываются при открытии/закрытии раздела импорта; отмена не меняет данные.
- Проверяются production-компоненты Vue/TypeScript; смена стека не меняет композицию остальных экранов.
