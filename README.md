# Муроблоки 🐈

Репозиторий: `aidagame`. Пользовательское название приложения — «Муроблоки».

Маленькие игры для отдыха. Первая готовая головоломка — **1010!** (Block Puzzle, поле 10×10).

Готовое статическое веб-приложение: работает в мобильном/десктопном браузере, устанавливается на экран iPhone, поддерживает игру офлайн после первого посещения и сохраняет прогресс на устройстве.

## Запуск локально

Требуется Node.js 20+. Внешних npm-зависимостей **нет**.

```bash
npm run dev
# http://localhost:4173
```

Нельзя проверять работу PWA простым открытием `index.html` через `file://`: сервис-воркер требует HTTP(S). Для проверки приложения иконку на iPhone добавляют уже с опубликованного HTTPS-домена.

Логические тесты:

```bash
npm test
```

## Публикация на GitHub Pages

1. Создайте пустой репозиторий GitHub, например `aidagame`.
2. Поместите **всё содержимое этой папки** в корень репозитория и отправьте в ветку `main`.
3. В **Settings → Pages** укажите Source: **GitHub Actions**.
4. Workflow `.github/workflows/pages.yml` сам опубликует приложение после push.
5. Откройте HTTPS-адрес, который GitHub выдаст после развёртывания.

Можно использовать GitHub только для хранения кода, а приложение публиковать через Coolify (ниже).

## Публикация на собственном VPS через Coolify

1. Создайте репозиторий и загрузите этот проект на GitHub.
2. В Coolify создайте новый ресурс из Git-репозитория с типом **Dockerfile**.
3. Используйте `Dockerfile` из корня проекта, порт контейнера **80**.
4. Укажите домен `https://muro.aidanastya.ru`, настройте DNS на VPS и выдачу TLS-сертификата через Coolify/reverse proxy.
5. Сохраните конфигурацию, разверните контейнер и откройте домен.

Для Docker используйте корневой `Dockerfile`, сборки Node.js не требуется. `nginx.conf` уже включён. Важно публиковать приложение по **HTTPS**, иначе PWA и service worker на телефоне не будут работать.

## Как добавить на iPhone

1. Откройте опубликованный HTTPS-сайт **в Safari**.
2. Нажмите «Поделиться».
3. Выберите «На экран Домой» (название пункта зависит от версии iOS).
4. Сохраните иконку «Муроблоки». Приложение будет открываться в самостоятельном окне.

Сохранения остаются **локальными для конкретного браузера / установленного веб-приложения**. Переход на другой телефон автоматически прогресс не переносит.

## Структура проекта

- `AGENTS.md` — правила работы с проектом.
- `docs/specs/` — четыре исходных ТЗ и изображения вайрфреймов; имена и содержимое сохранены.
- `docs/assets/icons/` — пять исходных SVG-референсов; рабочие иконки приложения остаются в `icons/`.

- `index.html` — оболочка и PWA-метатеги.
- `src/main.js` — экраны, взаимодействия, навигация, отрисовка.
- `src/styles.css` — адаптивная композиция, дизайн-токены, анимации.
- `src/game/shapes.js` — нормализация каталога и ориентации фигур.
- `src/game/logic.js` — чистая игровая логика без DOM.
- `src/storage/db.js` — IndexedDB, формат сохранений, задел под JSON-бэкапы.
- `src/design/themes.js` — 6 тем × 2 режима, 6 рисунков, 5 групп фигур.
- `icons/*.svg` — логотип и предоставленные SVG-рисунки для игровых клеток.
- `pwa/` — иконки для веб-приложения и домашнего экрана iPhone.
- `manifest.webmanifest`, `sw.js` — установка и офлайн-кэш.
- `tests/logic.test.js`, `tests/design.test.js` — тесты механики и палитр на стандартном Node test runner.
- `Dockerfile`, `deploy/nginx.conf`, `.github/workflows/pages.yml` — развёртывание.

## Что важно знать перед публикацией

1. **Технический документ из исходных материалов обрывается посреди п. 5.4.** Поэтому ниже этого места неизвестны окончательные требования к серверному резервному копированию. Серверный API и SQLite **не реализованы**: они были обозначены как предлагаемое дополнительное средство, но полный контракт отсутствует. В проекте подготовлены локальные `exportBackup` / `importBackup`, пока без пользовательского интерфейса.
2. В исходном ТЗ Vue 3 **рекомендован, но не утверждён**. Для простоты публикации использованы нативные JavaScript ES-модули, CSS и IndexedDB без сборки. Этот выбор не меняет правила игры и позволяет позже перейти на Vue без переписывания чистой логики.
3. **2048 и Tap Match не реализованы**, согласно последнему продуктовому решению. Только карточки-заглушки.
4. На iOS Safari, после установки и офлайн-игры, требуется ручная проверка на реальном устройстве: автоматизировано в Chromium проверены размеры и перемещение фигур мышью / касанием; реальный iPhone в тестовой среде недоступен.
5. При изменении списка файлов приложения и нового релиза следует обновлять имя `CACHE` в `sw.js`, чтобы прежний кеш корректно заменился.
6. Значения исходного баланса — **предварительные** из игрового ТЗ; до запуска на большую аудиторию полезно вручную проверить частоты и длительность партий.

**Авторские материалы:** приложение использует пользовательские визуальные референсы и переработанный пиксельный логотип; никакая внешняя коммерческая лицензия на них не подразумевается.
