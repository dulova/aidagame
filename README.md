# Муроблоки 🐈

Маленькие игры для отдыха. Первая игра — **1010!**: поле 10×10, 27 ориентаций фигур, три слота, очистка линий, очки и рекорд.

Версия **1.2.0**, Vue 3 + Vite + TypeScript. Репозиторий: [dulova/aidagame](https://github.com/dulova/aidagame). Адрес GitHub Pages: [dulova.github.io/aidagame](https://dulova.github.io/aidagame/).

## Запуск и проверки

Рекомендуется Node.js 24 LTS; минимум 22.12. Зависимости устанавливаются из lock-файла.

```bash
npm ci
npm run dev
# http://localhost:5173/aidagame/

npm run check
# типы, 23 теста, production-сборка, бюджеты размера

npx playwright install chromium webkit
npm run test:e2e
# production-сборка должна быть подготовлена командой check/build

npm run preview
# http://localhost:4173/aidagame/
```

`file://` не подходит для проверки приложения. PWA проверяется через production preview по HTTP на localhost либо по опубликованному HTTPS-адресу.

## Что работает

- Игра мышью: перетаскивание или выбор двумя кликами; клавиатура: выбор фигуры, стрелки, Enter/Пробел, Escape. Касанием — перетаскивание с фигурой выше пальца, без размещения коротким тапом.
- Шесть тем: Пастель, Зима, Весна, Лето, Осень, Ай Да Настя; у каждой светлый и тёмный режим. Палитры и идентификаторы сохранены.
- Рисунки: Однотонный, Лапка, Снежинка, Сердечки, Лист, Тыковка. SVG работают в слотах, на поле, при перетаскивании и офлайн.
- Неподвижная подложка из 100 клеток, короткий каскад исчезновения блоков, плавная установка и возврат. Учитывается уменьшение движения в системных настройках.
- Партия и настройки в IndexedDB; рекорд хранится отдельно. Миграция прежней базы и прежнего localStorage сохраняет данные. Накопленные счётчики прошлых партий отложены.
- Достоверные ошибки записи, повтор сохранения, экспорт состояния из памяти. Проверка ревизий предотвращает тихую перезапись другой вкладкой, даже без BroadcastChannel.
- **Экспорт сохранений** и **Импорт сохранений** внизу настроек. Предпросмотр и подтверждение полного восстановления; поддерживаются старый JSON v1 и новый v2. Отмена, неверный файл и ошибка записи сохраняют предыдущие данные. Импорт восстанавливает рекорд из файла, даже если он меньше текущего.
- PWA: офлайн после подтверждённого кэширования, предложение обновления в безопасный момент, проверенный переход со старого Service Worker без потери партии.
- Адаптивные экраны меню, настроек, игры и результата. 2048 и Tap Match остаются карточками «скоро в игре».

Игровые правила сохранены. Согласованное изменение генератора: новая тройка должна иметь допустимый ход, если он возможен; обязательная маленькая фигура больше не навязывается.

## Сохранения и iPhone

Данные локальны для браузера/установленного приложения. Серверного резервирования и автоматической синхронизации нет. Для переноса на другой телефон или origin сначала экспортируйте файл из прежней установки, затем импортируйте его на новом адресе. Файл экспорта нужно сохранить самостоятельно.

В Safari откройте HTTPS-адрес → «Поделиться» → «На экран Домой». Перед игрой без сети дождитесь сообщения «Готово к игре офлайн». Автоматические проверки Chromium и WebKit выполнены; установка и жесты на физическом iPhone требуют ручной проверки.

## Публикация

Vite использует `base: '/aidagame/'`. GitHub Actions при pull request проверяет типы, unit/integration, build, размеры и браузерные сценарии. После merge/push в `main` тот же процесс публикует только `dist/` через GitHub Pages. В Settings → Pages должен быть выбран Source → GitHub Actions.

Не публикуйте исходный корень вместо `dist/`. VPS, Docker, API и SQLite для этого релиза не требуются. Корневые `Dockerfile` и `deploy/` сохранены как исторические материалы и не используются этим процессом публикации.

## Структура

```text
.github/workflows/pages.yml    проверки и GitHub Pages
AGENTS.md                     правила разработки
index.html                    точка входа и PWA-метатеги
package.json, package-lock.json
vite.config.ts                base и PWA
playwright.config.ts          Chromium/mobile Chromium/WebKit
vitest.config.ts, tsconfig.json
src/
  main.ts, App.vue            запуск, экраны и операции пользователя
  components/                 поле, фигуры, диалоги, иконки
  game/logic.ts, shapes.ts     чистые правила и фигуры
  game/registry.ts            контракт и каталог игр
  storage/repository.ts      миграции, транзакции, ревизии, JSON
  design/themes.js           прежние палитры и рисунки
  styles.css                 композиция, темы и анимации
public/icons/, public/pwa/   ресурсы production-сборки
public/cleanup-legacy.js     очистка только устаревшего кэша
icons/, pwa/                 сохранённые исходные ресурсы
scripts/                     замеры и проверка размера
tests/                      логика, палитры, хранение, браузер
  fixtures/v1/               неизменяемая прежняя версия для теста обновления
docs/specs/                  четыре согласованных ТЗ и вайрфреймы
docs/release-scope.md         решения и границы 1.2.0
docs/verification/           матрица требований, результаты, замеры
```

`dist/`, `node_modules/`, отчёты Playwright и временные скриншоты в Git не включаются. Manifest и Service Worker генерируются сборкой. Исходные картинки вайрфреймов и SVG-референсы сохранены в `docs/`.

## Приёмка и дальнейшая работа

[Согласованный объём](docs/release-scope.md), [матрица требований и тестов](docs/verification/report.md), [данные сравнения производительности](docs/verification/performance.json).

Перед будущим откатом к коду до миграции сначала экспортируйте данные: старая версия базы несовместима с IndexedDB версии 2. Для исправлений предпочтителен новый совместимый выпуск. Исходный баланс фигур остаётся предварительным и требует наблюдения за реальными партиями.

Авторские материалы: пользовательские визуальные референсы и переработанный пиксельный логотип; внешняя коммерческая лицензия на них не подразумевается.
